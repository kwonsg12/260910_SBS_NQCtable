# PR4: 대근 배정과 비번 보장 계산 수정

## 수정한 사례

- 야·조 휴가의 첫 대근자가 다음 날 비번 보장, 휴가, 교육, 다른 근무 또는 적용 기간 종료로 투입될 수 없으면 제외합니다. 다른 후보가 있으면 그 사람을 검토합니다.
- 신청자도 첫날 야근·다음 날 조근이고 두 날짜 모두 적용 기간 안이어야 합니다. 빠른 날짜 선택 목록과 직접 입력한 신청에 같은 조건을 적용합니다.
- 첫 대근자의 다음 날 일근은 기존 규칙대로 2차 대근자로 메웁니다. 두 날짜 모두 비번이면 2차 대근은 필요 없습니다. 가능한 조합이 없으면 사유를 표시하고 자동 배정을 중단합니다.
- 승인 대기·승인된 비번 보장은 대근 제외와 월 한도에 반영합니다. 반려·취소는 제외합니다. 기존 데이터에 같은 날짜가 중복 저장됐더라도 한도는 하루 한 번으로 계산합니다.
- 보장 날짜를 달력에 직접 입력하거나 신청 버튼을 여러 번 눌러도 같은 직원·같은 날짜의 유효한 신청은 추가하지 않습니다. 지난 날짜와 직원 적용 기간 밖의 신청도 차단합니다.
- 미리보기 후 현재 화면의 배정 조건이 달라졌다면 다시 미리보기를 보도록 안내합니다. 성공한 미리보기는 한 번만 확정할 수 있습니다.
- 날짜 미선택 시 보장 사용량 안내는 고정된 2026년 8월 대신 현재 월을 표시합니다.

## 범위

기존 신청 기록을 수정하거나 삭제하지 않습니다. 새로운 신청의 계산·검증과 한도 표시를 고칩니다.

다른 PC의 저장과 충돌하는 문제는 PR2의 범위입니다. 이번 확정 재검증은 현재 브라우저에 있는 상태를 기준으로 하며, 다른 PC의 최신 상태를 자동으로 가져오지는 않습니다.

원본 master에서 독립적으로 작성했습니다. PR1~3 없이 단독 적용할 수 있습니다. PR3와 함께 반영할 때는 PR3 security.js의 비번 보장 한도 검증도 아래 규칙에 맞춰야 합니다. 현재 PR3는 반려 건을 포함해 세므로, 이 화면 수정만 합치면 일부 정상 신청을 서버가 거절할 수 있습니다.

- cancelled뿐 아니라 rejected도 제외
- 같은 직원·같은 월의 유효 신청 날짜를 Set으로 모아 중복 날짜는 한 번만 계산
- 같은 날짜의 유효 신청을 직접 API로 추가하는 것도 거절

## 검증

npm test로 실제 index.html의 계산 함수와 신청 핸들러를 실행합니다. 정상 일근/야·조, 월 경계, 다음 날 보장·교육·퇴사, 후보 대체, 2차 대근 제외, 잘못된 날짜, 반려/취소/기존 중복, 한도 초과, 중복 신청, 미리보기 변경과 중복 확정을 확인합니다. 별도 라이브러리 설치나 운영 DB가 필요 없습니다.
