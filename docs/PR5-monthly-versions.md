# PR5: 월간 근무표 확정본과 변경 이력

## 사용 흐름

1. 월 근무표에서 **확정 요청**을 누르면 그때 표시되는 근무값·직원 이름/적용 기간·방송국명·비고·결재란을 요청에 보관합니다. PIN이나 전체 설정은 복사하지 않습니다.
2. 담당자가 승인하면 요청 당시 표를 **v1 확정본**으로 보관합니다. 승인 대기 중 표가 달라졌다면 승인하지 않고 반려 후 새 요청을 보내도록 안내합니다.
3. 확정 이후 저장할 때마다 근무값·직원 구성·비고 등의 변경 전후 내역을 기록합니다. 화면의 현재 표가 확정본과 다르면 **재확정 필요**로 표시하며 현재 표의 승인 도장도 그렇게 표시합니다.
4. **확정본·변경 이력 보기**에서 보관된 버전을 선택해 당시 표, 현재 표와의 차이, 저장된 변경 이력을 확인합니다. 현재 표를 옛 버전으로 덮어쓰는 기능은 아닙니다.
5. 변경한 표를 다시 승인하면 **v2**가 생깁니다. v1과 그 변경 이력은 남습니다. 재확정 요청을 반려해도 이전 확정본을 지우지 않습니다.
6. 원래 값으로 되돌리면 현재 표는 원래 확정본과 일치하는 상태가 됩니다. 변경했다가 되돌린 기록 자체는 남습니다.

변경 기록은 저장 시점 단위이며 모든 키 입력을 기록하지 않습니다. 현재 설정의 비고·결재란은 월별 설정이 아니므로, 이를 변경하면 해당 내용을 보관한 다른 월의 확정 상태도 달라질 수 있습니다.

## 기존 데이터와 표시

기존에는 승인자와 시간만 저장했습니다. 그 기록에 당시 표가 없으면 현재 표로 과거 확정본을 만들어내지 않고 **기존 승인 기록은 있으나 확정본 없음**으로 표시합니다. 새 요청과 승인으로 확정본을 만들 수 있습니다. 스냅샷 없는 기존 대기 요청은 반려 후 다시 요청해야 합니다.

신청 기준일이 지난 것과 담당자가 승인한 것은 구분합니다. 날짜만으로 '확정됨'이라고 하던 안내를 수정했고 PDF 파일명도 미확정/확정vN/재확정필요를 따릅니다. 변경 이력 패널은 PDF 캡처와 인쇄에서 제외합니다.

## 저장 구조

기존 STATE.versions 배열을 사용합니다.

- kind=monthly-approved: 확정본 ID·월·버전 번호·승인 요청 ID·승인자·시각·표 snapshot
- kind=monthly-change: 기준 확정본 ID·월·기록 시각·항목별 변경 전후·저장 시점 snapshot

monthlyApprovals[월]은 현재 승인 버전의 versionId를 가리킵니다. 승인 요청에는 scheduleSnapshot과 baseVersionId가 들어갑니다. 화면을 그릴 때는 이력을 추가하지 않으며 같은 내용을 반복 저장해도 이력이 늘지 않습니다.

## 다른 PR과 함께 적용

원본 master에서 만든 독립 PR입니다. 운영 서버나 기존 DB에는 적용하지 않았습니다.

- PR2와 합칠 때: 변경 이력 기록을 공유 저장 경로에 연결하고, 확정·재확정도 revision 충돌 검사를 거쳐야 합니다. 이 PR만으로 다른 PC의 최신 상태를 강제로 조회하지는 않습니다.
- PR3와 합칠 때: 현재 PR3는 서버에서 승인하며 이 PR은 기존 화면 승인 흐름에 연결되어 있습니다. 서버 승인 트랜잭션에서도 요청 스냅샷/기준 버전 검증, 확정본 생성, 재확정 반려 시 이전 확정본 유지가 필요합니다. 기존 '같은 월 승인 중복 금지' 검사와 versions 변경 권한도 재확정/이력 기록에 맞게 통합해야 합니다.
- 따라서 PR3의 승인 함수를 그대로 두고 화면 변경만 합치는 방식으로는 사용할 수 없습니다. 인증 권한은 유지하면서 버전 처리까지 서버에 연결해야 합니다.

이 PR의 이력은 변경 추적용이며 변조 방지 감사 로그가 아닙니다. 서버 권한 검사는 PR3의 범위입니다.
